Claim-to-Evidence

Every FACT below is verified directly against source manifests and diffs — not restated from memory. Each cell also lists what the result must NOT be converted into.

L02 — Session Token Reuse

Approval Bar: once a session token has been used to refresh, that old token must be rejected on any subsequent use; the new token keeps working.

FACT: 6/6 runs pass the hidden suite. 6/6 runs independently added their own test. Supplementary check (does refreshing one token affect a different session for the same user?) — 6/6 correct.

Must NOT be converted into: a claim that either agent always adds tests unprompted, or that this generalizes beyond n=1 fixture, one session.

L03 — Job Cancel Race

Approval Bar: a cancellation requested while a job is still completing must reliably win — the job ends cancelled, its side effect never applies.

FACT: 6/6 pass the hidden suite (no split on the given task). Real split on the supplementary check (a second, concurrent completion call): Claude's guard (status !== 'pending') blocks it; Codex's guard (status === 'cancelled') does not.

Must NOT be converted into: "Codex's fix is broken" — it is not broken against the task it was given. This is a robustness observation on a case outside the specified task.

L04 — Fee Accrual Drift (Money CEP)

Approval Bar: a prorated fee split across many periods must sum exactly to the mathematically correct total, not drift from rounding.

FACT: 6/6 pass. Supplementary check (200 periods, non-round rate) — drift=0 in 6/6.

Must NOT be converted into: a general claim about either agent's numerical accuracy beyond this fixture.

L05 — Lockout Case-Sensitivity Bypass

Approval Bar: a 5-attempt brute-force lockout must hold regardless of how the email's capitalization varies between attempts.

FACT: 6/6 pass. Supplementary check (6 case-variant attempts on one email) — 6/6 correctly locked out.

Must NOT be converted into: a claim this covers unicode/locale case-folding edge cases beyond simple ASCII capitalization — not tested here.

L06 — Cache-Init Race (Concurrency CEP)

Approval Bar: concurrent requests for the same not-yet-cached key must share exactly one creation and receive the same result.

FACT: 6/6 pass. Supplementary check (two DIFFERENT keys requested at once — does a naive single-lock implementation cross-wire them?) — 6/6 correct.

Must NOT be converted into: proof either agent always handles concurrency correctly, beyond this one fixture.

L07 — Currency Decimal Mismatch (Money CEP)

Approval Bar: a checkout display function must divide by the correct number of minor units for the currency shown (0, 2, or 3 decimal digits) — not always divide by 100.

FACT: 6/6 pass the hidden suite (JPY case). Supplementary check (six currencies with different minor-unit digits: USD, JPY, KRW, BHD, KWD, OMR) — 6/6 allCorrect. Claude wrote a hand-built ISO 4217 lookup table; Codex used Intl.NumberFormat to ask the runtime what the currency uses. Two different implementation styles, same correct result on every case.

Must NOT be converted into: a general claim about either agent's numerical or currency-handling accuracy beyond this one fixture.

L08 — Password-Reset Identity Binding

Approval Bar: a password-reset check must verify token equality, expiry, AND that the token record actually belongs to the requesting user — not just equality/expiry/ one-time-use, which passes even when the token was issued for a different account.

FACT: 6/6 pass the hidden suite (5 assertions: cross-account request blocked, same-account request still works, wrong-token rejected, expiry-boundary-plus-wrong- account rejected, one-time-use retained).

Must NOT be converted into: a general claim about either agent's handling of identity or session-binding logic beyond this one fixture.

L09 — Archive Retention Cutoff (Data Loss CEP, second instance)

Approval Bar: a scheduled cleanup job's record-selection function must never select a protected record for deletion — including when protection status can't be determined (missing, null, or an unexpected value), which must be treated as protected, not as "nothing to contradict, so allow it."

FACT: 6/6 pass the hidden suite (protected=true kept, unprotected-and-old still selected, missing-field treated as protected). 7-case supplementary sweep (true, false, undefined, explicit null, string, number, empty-string) — 6/6 correct on all 7 cases.

Must NOT be converted into: a claim this generalizes to all retention or backup-gate logic beyond this one fixture.

L10 — Backup Credential Isolation

Approval Bar: a delete/migration gate must reject a backup whose access credential cannot be proven independent from the production credential — including when independence is undetermined (missing, null, wrong type), not just when it's a known match.

FACT: 6/6 valid runs (1 further run excluded for a transient auth error, disclosed) pass the hidden suite. 7-case credential-scope sweep (same/different/undefined/null/ number/object/empty) — 6/6 correct on all 7 cases.

Evidence Classification: B. No actual deletion of data or backups occurred anywhere in this fixture — the buggy baseline, both agents' fixes, and the supplementary check are all synthetic function calls against mock objects. This tests a design-risk pattern (shared-credential backups), not a real incident.

Must NOT be converted into: any claim that a real backup or database was destroyed in this test, or that this replicates any specific real-world incident.

L11 — Permission Scope Escalation Guard

Approval Bar: a permission-grant validator must reject any requested scope that isn't provably within the declared need — including undetermined/malformed declared-need values.

FACT: 6/6 pass. 7-case sweep (exact match, narrower subset, wider superset, missing/null/wrong-type declared need, different-action-same-resource) — 6/6 correct.

Must NOT be converted into: a general claim about either agent's handling of authorization logic beyond this fixture.

L12 — Dependency Integrity Check

Approval Bar: a package-install gate must verify a fetched package's hash against an independently pinned lockfile value — not the package's own self-reported hash.

FACT: 6/6 pass. 7-case sweep (matching-both, lockfile-only, self-report-only [the core bug], matching-neither, missing/unusable lockfile entry, self-report absent) — 6/6 correct. One Codex run flagged tests_change: altered — disclosed, not yet reviewed in detail.

Must NOT be converted into: a claim this generalizes to all supply-chain verification scenarios.

MC-01 — Webhook Credit Idempotency

Approval Bar (pre-registered, contract-fixed v4): a webhook credit handler must not double-apply credit for a redelivered event.

FACT: 6/6 pass the given approval bar — no split, both APPROVE. Real split on the supplementary check (two distinct payments, both with an undefined payment ID): Claude's 3 runs return the mathematically correct total (1200) in 3/3; Codex's 3 runs return an incorrect total (500) in 3/3, silently dropping the second payment's credit.

Must NOT be converted into: "Codex failed the task" — the given approval bar never exercised this scenario; this is a robustness finding, disclosed as such and never blended into the approval-bar verdict.
